# 开发 RoadMap

## 1. 规划目标

以 6 周完成可部署的 `v1.0` 为目标，优先验证 Open-Meteo Weather/Marine 的数据可得性、许可和双端点合并，再实现确定性分析和可用 Dashboard。该计划适用于一名主要开发者的目标节奏；Stormglass/WorldTides 采购和 NOAA 文件管线不阻塞 MVP。

## 2. 总体阶段

| 阶段 | 周期 | 目标 | 核心交付物 |
| --- | --- | --- | --- |
| 阶段 0：可行性与骨架 | 第 1 周 | 消除数据源和架构最大风险 | Open-Meteo 双端点验证、解决方案、CI、标准模型 |
| 阶段 1：可查询 MVP | 第 2 周 | 从地点到逐小时标准预报 | 地点搜索、Provider、缓存、基础 Dashboard |
| 阶段 2：核心分析 | 第 3-4 周 | 形成产品核心决策能力 | Gate、评分、活动、趋势、时间窗、黄金测试 |
| 阶段 3：产品完善 | 第 5 周 | 完成日常可用流程 | 地图、收藏/历史、设置、AI 或潮汐首个增量 |
| 阶段 4：上线交付 | 第 6 周 | 安全、稳定、可运维地发布 | Docker、监控、安全、E2E、备份回滚、v1.0 |

## 3. 阶段 0：第 1 周

### 目标

在投入大量 UI 和业务代码前，确认 Open-Meteo Weather API 与 Marine API 是否能合法、稳定地提供 P0 字段、目标区域、时间分辨率和可接受配额，并验证两个端点的时间轴组装。

### 任务

- 确认 Open-Meteo 非商业/商业条款、缓存、署名、免费额度和商业升级路径。
- 用东极岛等 3-5 个代表坐标分别验证 Weather 与 Marine 的风、阵风、浪、风浪、涌浪、周期、方向、CAPE 和能见度。
- 保存两个端点的脱敏契约样本，确认单位、时间、底层模型、实际网格点和风浪方向语义。
- 验证一次 24h/72h/7d 用户查询实际产生的外部调用数和缓存命中后的成本模型。
- 建立 .NET 10 解决方案、分层项目、测试项目、EditorConfig 和 CI。
- 定义 Weather/Marine/Tide Provider 端口、`ForecastBatch`、`ForecastSnapshot`、质量状态和错误模型。
- 建立 PostgreSQL/SQLite 基础配置和首个迁移。
- 完成最小健康检查、结构化日志和 OpenTelemetry Trace。

### 退出条件

- Open-Meteo Weather/Marine 的 P0 数据能力和许可已确认，或已明确缺失项及可接受的降级范围。
- 正常/错误 Provider 样本可被自动解析。
- `dotnet build` 和基础测试在 CI 通过。

若 Open-Meteo 无法提供关键海况字段，且 Stormglass 的预算/许可也不成立，项目不得用缺失数据继续生成完整海况评分；应缩小 MVP 能力或调整数据方案。

## 4. 阶段 1：第 2 周

### 任务

- 已完成 `MI-0014`：实现预置地点目录、地名搜索、附近地点查询和分析 `locationId` 解析；收藏和外部地理编码仍不在本项范围。
- 实现 `OpenMeteoWeatherProvider`、`OpenMeteoMarineProvider`、分域标准化和质量校验。
- 实现 `ForecastSnapshotAssembler`，按 UTC 合并多个来源批次并保留指标级来源。
- 实现 24h/72h/7d 预报批次与逐小时存储。
- 通过 `IForecastBatchRepository` 追加并读取 24/72/168 小时批次，保留点位质量、缺失指标和逐指标来源引用。
- 实现 L1 缓存、可选 Redis 契约、单航班回源和 Stale 降级。当前已完成标准预报 L1 `IMemoryCache`、版本化键、可替换缓存端口和单航班协调器；Redis 适配器和 L2 分布式锁仍待后续多实例任务。
- 建立 `POST /api/v1/marine-analyses` 的 metrics-only 查询骨架，返回逐小时指标、质量摘要、来源批次和缓存状态；评分、活动分析和分析持久化留待后续任务。
- 已完成 `MI-0015`：实现 Blazor Dashboard 查询栏、数据来源状态、关键指标网格和逐小时指标表；当前仍为 metrics-only 展示，不生成评分、活动建议或推荐时间窗。
- 建立 Provider 契约测试和 API 集成测试。

### 退出条件

用户可选择地点和时间范围，稳定看到标准化逐小时数据、来源、更新时间和缺失状态。当前阶段 1 查询闭环已由 `MI-0015` 覆盖；本次按用户指令不执行截图验证，视觉效果由用户自行人工验证。

## 5. 阶段 2：第 3-4 周

### 第 3 周：规则与评分

- 已完成 `MI-0016`：实现单小时 Safety Gates、基础惩罚、等级映射和规则代码；暂未接入 API/Dashboard。
- 已完成 `MI-0016`：实现风小浪大、阵风异常、短周期、长周期岸边风险和低能见度 Gate/组合规则；`MI-0018` 已补充时间窗后的风险快速上升识别；岸线暴露仍待后续任务。
- 已完成 `MI-0017`：实现海钓、乘船、登岛、露营、摄影 Activity Profile，并按活动乘数生成逐小时活动分数。
- 实现算法参数 Schema、版本实体和发布前校验。
- 建立 GS-001 至 GS-010 黄金样本和阈值边界测试。

### 第 4 周：趋势与解释

- 已完成 `MI-0017`：实现逐小时综合/活动评估、置信度和算法版本投影；`MI-0018` 已实现推荐窗口和返航截止投影。
- 已完成 `MI-0017`：实现风险贡献、数据质量和算法版本的 API 投影。
- 已完成 `MI-0017`：实现 Dashboard 活动分数、风险摘要和逐小时评分表；`MI-0018` 已实现推荐时间窗列表、风险上升提示和返航截止。趋势 Tabs、小时详情和图表时间带仍待后续。
- 完成缓存键与算法版本联动。
- 使用经验样本和官方预警案例评审初始阈值。

### 退出条件

- 所有 P0 风险规则可解释、可追溯并通过边界测试。
- “风小浪大”、雷暴、缺失数据和风险上升场景符合 SRS。
- Dashboard 能回答是否适合、原因和建议时段。

## 6. 阶段 3：第 5 周

### P1 必做

- Leaflet/OpenStreetMap 全宽选点与地图失败降级。
- ASP.NET Core Identity、收藏地点、查询历史和用户单位设置。
- 移动端导航、360px 布局、键盘和基础可访问性。
- 管理员 Provider 状态、算法版本列表和审计查询。
- 接入 WorldTides 潮汐、Credit 余额告警、长 TTL 缓存和无潮汐降级。

### P1 可选增量

在 WorldTides 基础潮汐完成后，根据进度选择一个完成闭环：

- **AI 解读**：结构化输出、事实校验、缓存和规则模板降级；或
- **Stormglass 技术预研**：使用免费调试额度验证多来源、海温和洋流字段，但不默认接入生产查询。

未选择的能力进入 `v1.1`，不以半成品阻塞 v1.0。NOAA/NCEP 文件解析固定进入 v2.0，不占用本阶段交付时间。

### 退出条件

注册用户可完成收藏和再次查询；桌面与移动核心流程可用；P1 增量具备完整失败降级。

## 7. 阶段 4：第 6 周

- 完成多阶段非 root Dockerfile、Compose、Secret 和反向代理配置。
- 完成 PostgreSQL 迁移 SQL、备份、恢复和回滚演练。
- 接入日志、指标、Trace、Provider 配额和关键告警。
- 执行性能、故障注入、安全、Playwright 和视觉回归测试。
- 修复 S1/S2 缺陷，完成操作手册、免责声明和数据署名。
- 发布 `v1.0.0`，观察 5xx、延迟、Stale、数据质量和 Unknown 比例。

## 8. 版本路线

| 版本 | 目标 | 范围 |
| --- | --- | --- |
| v0.1 | 数据可行性 | Open-Meteo Weather/Marine 验证、多来源标准模型、CLI/API 样例 |
| v0.2 | 查询 MVP | 地点、双端点逐小时预报、快照组装、缓存、基础 Dashboard |
| v0.3 | 核心分析 | Gate、评分、活动、趋势和时间窗 |
| v0.4 | 产品 Beta | 地图、登录、收藏、WorldTides、移动适配、P1 增量 |
| v1.0 | 可部署版本 | 稳定性、安全、监控、测试和文档 |
| v1.1 | 数据增强 | Stormglass 专业字段、AI 剩余能力、多模型对比 |
| v2.0 | 自有数据管线 | NOAA/NCEP GRIB2/NetCDF、NDBC 校准、洋流、航线和模型校准 |

## 9. 依赖关系

```mermaid
flowchart LR
    A[Open-Meteo 双端点与许可验证] --> B[多来源标准批次]
    B --> C[快照组装、Provider 与缓存]
    C --> D[评分与活动分析]
    D --> E[趋势与推荐窗口]
    E --> F[AI 解读/通知]
    B --> G[Dashboard]
    D --> G
    C --> T[WorldTides 潮汐]
    C -.v1.1.-> S[Stormglass 增强]
    C -.v2.0.-> N[NOAA/NCEP + NDBC 管线]
    G --> H[E2E 与上线]
```

AI、UI 星级和通知都依赖确定性分析；不得先用 AI 文本替代尚未实现的评分规则。

## 10. 主要风险与缓冲

| 风险 | 影响 | 缓解 | 缓冲 |
| --- | --- | --- | --- |
| Open-Meteo 免费/商业条款不适用 | 阶段 0-1 阻塞 | 首周确认条款和商业升级预算 | 2-3 天 |
| Weather/Marine 时间轴或模型不一致 | 评分输入错位 | 分批次保存、UTC 组装和契约测试 | 2 天 |
| Stormglass 调用成本失控 | v1.1 成本超支 | 默认关闭、每日硬预算、禁止匿名自动 fallback | 不阻塞 v1.0 |
| WorldTides Credit 耗尽 | 潮汐降级 | 长 TTL 缓存和余额告警 | 1 天 |
| NOAA 文件解析复杂度超预期 | v2.0 延期 | 后台管线、固定样本、独立技术验证 | 不阻塞 v1.x |
| 方向/时间/单位映射错误 | 评分整体错误 | 契约样本和人工对照 | 2 天 |
| 阈值缺少真实样本 | 误报/漏报 | 保守规则、黄金集、版本化 | 持续校准 |
| UI 范围扩张 | 核心延期 | 首屏聚焦决策，P2 后置 | 2-3 天 |
| AI 不稳定 | P1 延期 | 规则模板为默认降级 | 不阻塞 v1.0 |
| 单人开发容量 | 计划滑动 | 每阶段设退出条件和可裁剪项 | 1 周发布缓冲可选 |

## 11. 每周验收与进度更新

每周结束更新：完成项、演示地址/截图、自动化测试结果、Provider 配额与数据问题、下周范围和阻塞项。未达到阶段退出条件时，优先完成核心闭环，不提前堆叠后续功能。
