# 测试方案

## 1. 测试目标

验证 Marine Insight 能正确接入并标准化海洋气象数据，在边界和组合风险下生成保守、稳定、可解释的结果，并在 Provider、缓存、AI、数据库和网络异常时按设计降级。

## 2. 测试范围

### 2.1 范围内

- 地点/时间查询、标准预报、综合和活动分析。
- 风、阵风、浪、周期、涌浪、雷暴、CAPE、能见度等规则。
- 推荐窗口、返航截止、置信度和算法版本。
- Open-Meteo Weather/Marine、Stormglass、WorldTides、NOAA/NDBC 契约，以及缓存、认证、收藏、历史和设置。
- Blazor 桌面/移动交互、地图、图表、错误和降级状态。
- 部署、迁移、健康检查、性能、安全和恢复。

### 2.2 暂不包含

- 未接入的洋流、航线、推送和原生移动端。
- 对第三方天气预报本身的气象准确率作绝对保证。
- 船型、载重和船长经验等未建模因素的安全认证。

## 5. Provider 测试

- Open-Meteo Weather 与 Marine 的正常 24/72/168 小时响应、目标海岛坐标和 UTC 时间轴合并。
- Provider 时间为 UTC、本地时间或含偏移时的映射。
- 风向/浪向语义、单位换算、降水累积周期。
- 数组长度不一致、重复时间、空字段、额外字段和字段删除。
- `401/403/404/429/5xx`、连接超时和无效 JSON。
- 认证失败不重试；429 尊重 `Retry-After`；瞬时故障重试次数受限。
- 契约样本不包含真实 API Key 和敏感响应头。
- ForecastSnapshotAssembler 验证 Weather/Marine/Tide 独立批次的 UTC 并集、最大最近点差、时间缺口、同域批次选择、同指标来源选择、来源实际时间和 Stale/Partial/Unknown 质量传递。
- ForecastBatchRepository 验证批次追加不可更新、24/72/168 小时范围往返、按地点/Provider/数据域/UTC 覆盖范围读取，以及缺失值不补零和来源追溯不丢失。
- ForecastBatchCacheCoordinator 验证 L1 命中不回源、Provider 失败时保留原 `FetchedAtUtc` 并将 `StaleData` 传递到批次/点位/指标来源、过期窗口外不返回旧值，以及相同键的并发单航班刷新。
- Stormglass 多来源数组必须保留来源，验证显式模型选择和分歧降置信度逻辑。
- WorldTides 验证潮位、极值时间、时区、基准面、Credit 余额和长 TTL 缓存。
- NOAA 使用固定 GRIB2/NetCDF 文件验证解码、经纬度网格定位和资源上限；NDBC 使用固定站点观测验证校准匹配。

在接入开发开始前，必须用真实 Open-Meteo Weather/Marine 接口验证 P0 字段、目标区域覆盖、免费/商业使用条款和一次用户查询的调用放大倍数；这是项目阻断性验收项。

## 6. 功能与 API 用例

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| TC-001 | 地名搜索重名地点 | 返回可区分候选，不自动误选 |
| TC-002 | 经纬度越界 | 400 + 字段错误 |
| TC-003 | 创建 72h 分析 | 返回来源、时间、算法、置信度和小时数据 |
| TC-004 | Weather/Marine 有效缓存命中 | 不调用对应 Provider，分别保留原 `fetchedAt` |
| TC-005 | Provider 失败 + 有效旧缓存 | 返回 Stale 状态和数据年龄 |
| TC-006 | Provider/缓存均失败 | 503 ProblemDetails + TraceId |
| TC-007 | 重复收藏 | 409 `FAVORITE_ALREADY_EXISTS` |
| TC-008 | 用户读取他人收藏 | 403/404，不泄露资源存在性 |
| TC-009 | AI 输出不合法 | 丢弃 AI，返回规则模板和成功分析 |
| TC-010 | 算法发布 | 新结果引用新版本，历史结果保持旧版本 |
| TC-011 | Weather 新批次 + Marine 旧批次 | `sources` 返回两个时间，整体置信度按较弱来源下降 |
| TC-012 | Stormglass 默认关闭 | Open-Meteo 失败时不产生付费调用 |
| TC-013 | WorldTides Credit 不足 | 潮汐降级，基础分析仍成功 |
| TC-014 | Weather/Marine 时间偏移在允许范围内 | 近似对齐并标记 `TimeGap`/`Partial`，保留来源实际时间 |
| TC-015 | 多 Provider 提供同一指标 | 无选择策略时报错，配置策略后只保留明确来源 |
| TC-016 | metrics-only 坐标查询 | 返回逐小时指标、质量状态、来源批次和 `cacheStatus` |
| TC-017 | 同坐标重复查询 | 第二次 Weather/Marine 均命中缓存，Provider 各调用一次 |
| TC-018 | metrics-only 非法小时数 | 返回 `400 VALIDATION_FAILED` ProblemDetails |
| TC-019 | metrics-only Provider 故障 | 返回 `503 PROVIDER_UNAVAILABLE` ProblemDetails 和 Trace-Id |
| TC-020 | 预置地点搜索 | 返回地点类型、坐标、时区和 `preset` 来源 |
| TC-021 | 附近地点查询 | 按距离排序，越界或缺失参数返回 `400 VALIDATION_FAILED` |
| TC-022 | 分析使用 `locationId` | 解析地点元数据；未知 ID 返回 `404 LOCATION_NOT_FOUND` |
| TC-023 | 分析返回活动评分 | `overall`、`activities`、`risks` 和逐小时评估可追溯到算法版本 |
| TC-024 | 未知活动参数 | 返回 `400 VALIDATION_FAILED`，不静默忽略 |
| TC-025 | 分析返回推荐窗口 | `recommendedWindows` 包含活动、开始/结束、返航截止、风险上升点、最佳分和最低门槛 |
| TC-026 | 分析 ETag 条件请求 | 响应根级算法版本、缓存身份和 `ETag` 一致；相同 `If-None-Match` 返回 `304` |

`MI-0074` 增加 Dashboard 样式与锚点回归：脚本契约必须使用 `block: "nearest"` 且不再使用 `block: "start"`；Playwright 在桌面和 360px 视口调用结果定位后，URL 保持 `#summary-title` 且查询区仍与视口相交；逐小时表头在明暗主题下均消费语义变量。

## 9. 故障与恢复测试

- Redis 启动失败、运行中断开和恢复。
- PostgreSQL 短暂断连、只读、磁盘不足和迁移缺失。
- Open-Meteo Weather 和 Marine 分别连续超时、独立熔断并在半开后恢复。
- Stormglass 达到每日预算后关闭付费 fallback，缓存和基础路径保持可用。
- WorldTides Credit 告警、接口失败和恢复。
- AI 限流、超时、错误 Schema 和事实不一致。
- 容器重启、SignalR 断线、反向代理 WebSocket 禁用。
- 备份恢复后应用能够读取地点、用户和历史分析。

## 10. 安全测试

- 收藏/历史/设置的 IDOR 和批量越权。
- Cookie 安全属性、CSRF、防暴力破解和限流绕过。
- 地点名、Provider 错误和 AI 文本中的 XSS 载荷。
- 日志、ProblemDetails、健康检查和管理页不泄露 Secret。
- 管理员算法发布要求正确 Policy 和审计。
