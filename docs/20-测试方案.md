# 测试方案

## 1. 测试目标

验证 Marine Insight 能正确接入并标准化海洋气象数据，在边界和组合风险下生成保守、稳定、可解释的结果，并在 Provider、缓存、AI、数据库和网络异常时按设计降级。

## 2. 测试范围

### 2.1 范围内

- 地点/时间查询、标准预报、综合和活动分析。
- 风、阵风、浪、周期、涌浪、雷暴、CAPE、能见度等规则。
- 推荐窗口、返航截止、置信度和算法版本。
- Open-Meteo Weather/Marine、Stormglass、WorldTides、NOAA/NDBC 契约，以及缓存、认证、收藏、历史和设置。
- Blazor 桌面/移动交互、地图、图表、错误和降级状态。
- 部署、迁移、健康检查、性能、安全和恢复。

### 2.2 暂不包含

- 未接入的洋流、航线、推送和原生移动端。
- 对第三方天气预报本身的气象准确率作绝对保证。
- 船型、载重和船长经验等未建模因素的安全认证。

## 3. 测试分层

| 类型 | 目标 | 工具/方式 |
| --- | --- | --- |
| Domain 单元测试 | 阈值、组合规则、等级、时间窗、置信度 | xUnit + FluentAssertions |
| Application 测试 | 用例编排、权限、取消、幂等和错误映射 | xUnit + NSubstitute/Fake |
| Provider 契约测试 | DTO、单位、时间、方向、缺失和协议变化 | 固定样本 + WireMock.Net |
| 数据库集成测试 | EF 映射、迁移、约束、并发、PostgreSQL 行为 | Testcontainers for PostgreSQL |
| 缓存集成测试 | L1/L2、TTL、锁、Stale 和 Redis 降级 | Redis Testcontainer |
| 组件测试 | 风险组件、表单、状态和授权视图 | bUnit |
| API 集成测试 | 路由、ProblemDetails、认证、限流 | WebApplicationFactory |
| E2E/视觉 | 用户主流程、移动布局、地图和图表 | Playwright |
| 性能测试 | 延迟、并发、缓存命中和 Provider 保护 | k6 或 NBomber |
| 安全测试 | 越权、CSRF、XSS、Secret、依赖漏洞 | 自动化 + 人工检查 |

当前持久化集成测试使用 SQLite 内存数据库执行现有迁移，覆盖 `IForecastBatchRepository` 对 24、72、168 小时批次的追加/按 ID 读取、点位指标空值、质量状态、缺失位图和逐指标来源引用，并覆盖按地点、Provider、数据域及覆盖范围筛选。SQLite 通过后仍需使用真实 PostgreSQL 验证 `DateTimeOffset` 范围谓词、索引计划、并发追加和约束行为。

当前缓存测试覆盖 `ForecastCacheKey` 的 Provider/模型/范围/标准化版本隔离和 UTC 小时边界，覆盖 L1 新鲜窗口、Provider 失败后的 `Stale` 窗口、窗口外错误传播、缓存后端故障旁路，以及 20 个并发请求只触发一次共享 Provider 刷新；Infrastructure 和 Web 测试同时验证 `IMemoryCache` 与协调器注册。

当前自动化测试共 75 个：Domain 10 个、Application 24 个、Infrastructure 24 个、Web 17 个。`MI-0013` 的 Web API 集成测试覆盖首次坐标查询的指标/质量/来源和 `miss` 投影、第二次查询的缓存命中与 Provider 单次调用、非法小时数的 `400 VALIDATION_FAILED`，以及 Provider 故障的 `503 PROVIDER_UNAVAILABLE` 和 Trace-Id；`MI-0014` 追加地点领域不变量、预置迁移、规范化搜索、附近距离排序、地点 API 和 `locationId` 分析输入测试。

## 4. 黄金样本集

每个算法版本必须回放固定样本，并保存输入、期望规则、等级和置信度。

| 编号 | 场景 | 关键输入 | 期望 |
| --- | --- | --- | --- |
| GS-001 | 平静海况 | 风 3、阵风 5、浪 0.3、周期 8、无雷暴 | 高分，无硬性风险 |
| GS-002 | 风小浪大 | 风 3、浪 2.5、涌浪 2.0 | Avoid，触发 `WIND_LOW_WAVE_HIGH` 和 Gate |
| GS-003 | 阵风突增 | 风 4、阵风 11 | 露营/乘船明显扣分 |
| GS-004 | 短周期颠簸 | 浪 0.8、周期 4 | 乘船/登岛短周期风险 |
| GS-005 | 长周期岸边风险 | 涌浪 0.9、周期 12 | 岸钓/登岛额外惩罚 |
| GS-006 | 雷暴 | Thunderstorm=true | 所有相关活动 Avoid |
| GS-007 | CAPE 高但无其他信号 | CAPE 1500、雷暴未知 | 提高关注，不单独伪造雷暴 |
| GS-008 | 低能见度 | 0.4 km | Safety Gate |
| GS-009 | 数据缺失 | 浪和涌浪均缺失 | Unknown/422，不补 0 |
| GS-010 | 风险即将上升 | 17:00 后跨越高风险阈值 | 推荐窗口提前结束并给返航缓冲 |

所有阈值测试覆盖 `threshold - epsilon`、`threshold`、`threshold + epsilon`。

## 5. Provider 测试

- Open-Meteo Weather 与 Marine 的正常 24/72/168 小时响应、目标海岛坐标和 UTC 时间轴合并。
- Provider 时间为 UTC、本地时间或含偏移时的映射。
- 风向/浪向语义、单位换算、降水累积周期。
- 数组长度不一致、重复时间、空字段、额外字段和字段删除。
- `401/403/404/429/5xx`、连接超时和无效 JSON。
- 认证失败不重试；429 尊重 `Retry-After`；瞬时故障重试次数受限。
- 契约样本不包含真实 API Key 和敏感响应头。
- ForecastSnapshotAssembler 验证 Weather/Marine/Tide 独立批次的 UTC 并集、最大最近点差、时间缺口、同域批次选择、同指标来源选择、来源实际时间和 Stale/Partial/Unknown 质量传递。
- ForecastBatchRepository 验证批次追加不可更新、24/72/168 小时范围往返、按地点/Provider/数据域/UTC 覆盖范围读取，以及缺失值不补零和来源追溯不丢失。
- ForecastBatchCacheCoordinator 验证 L1 命中不回源、Provider 失败时保留原 `FetchedAtUtc` 并将 `StaleData` 传递到批次/点位/指标来源、过期窗口外不返回旧值，以及相同键的并发单航班刷新。
- Stormglass 多来源数组必须保留来源，验证显式模型选择和分歧降置信度逻辑。
- WorldTides 验证潮位、极值时间、时区、基准面、Credit 余额和长 TTL 缓存。
- NOAA 使用固定 GRIB2/NetCDF 文件验证解码、经纬度网格定位和资源上限；NDBC 使用固定站点观测验证校准匹配。

在接入开发开始前，必须用真实 Open-Meteo Weather/Marine 接口验证 P0 字段、目标区域覆盖、免费/商业使用条款和一次用户查询的调用放大倍数；这是项目阻断性验收项。

## 6. 功能与 API 用例

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| TC-001 | 地名搜索重名地点 | 返回可区分候选，不自动误选 |
| TC-002 | 经纬度越界 | 400 + 字段错误 |
| TC-003 | 创建 72h 分析 | 返回来源、时间、算法、置信度和小时数据 |
| TC-004 | Weather/Marine 有效缓存命中 | 不调用对应 Provider，分别保留原 `fetchedAt` |
| TC-005 | Provider 失败 + 有效旧缓存 | 返回 Stale 状态和数据年龄 |
| TC-006 | Provider/缓存均失败 | 503 ProblemDetails + TraceId |
| TC-007 | 重复收藏 | 409 `FAVORITE_ALREADY_EXISTS` |
| TC-008 | 用户读取他人收藏 | 403/404，不泄露资源存在性 |
| TC-009 | AI 输出不合法 | 丢弃 AI，返回规则模板和成功分析 |
| TC-010 | 算法发布 | 新结果引用新版本，历史结果保持旧版本 |
| TC-011 | Weather 新批次 + Marine 旧批次 | `sources` 返回两个时间，整体置信度按较弱来源下降 |
| TC-012 | Stormglass 默认关闭 | Open-Meteo 失败时不产生付费调用 |
| TC-013 | WorldTides Credit 不足 | 潮汐降级，基础分析仍成功 |
| TC-014 | Weather/Marine 时间偏移在允许范围内 | 近似对齐并标记 `TimeGap`/`Partial`，保留来源实际时间 |
| TC-015 | 多 Provider 提供同一指标 | 无选择策略时报错，配置策略后只保留明确来源 |
| TC-016 | metrics-only 坐标查询 | 返回逐小时指标、质量状态、来源批次和 `cacheStatus` |
| TC-017 | 同坐标重复查询 | 第二次 Weather/Marine 均命中缓存，Provider 各调用一次 |
| TC-018 | metrics-only 非法小时数 | 返回 `400 VALIDATION_FAILED` ProblemDetails |
| TC-019 | metrics-only Provider 故障 | 返回 `503 PROVIDER_UNAVAILABLE` ProblemDetails 和 Trace-Id |
| TC-020 | 预置地点搜索 | 返回地点类型、坐标、时区和 `preset` 来源 |
| TC-021 | 附近地点查询 | 按距离排序，越界或缺失参数返回 `400 VALIDATION_FAILED` |
| TC-022 | 分析使用 `locationId` | 解析地点元数据；未知 ID 返回 `404 LOCATION_NOT_FOUND` |

## 7. UI 与可访问性测试

- 360x800、390x844、768x1024、1440x900 和宽屏视口。
- 查询工具栏、地点长文本、活动切换、指标网格和风险警示无重叠。
- 加载骨架、旧结果刷新、部分数据、Stale、错误、离线和重连状态。
- 地图点击可选坐标，地图失败时仍可输入经纬度。
- 图表 Canvas/SVG 非空，数据与 Tooltip 正确，Tab 切换不改变布局高度。
- 键盘完成搜索、选择、提交、Tabs、抽屉关闭和收藏操作。
- 风险在灰度/色觉差异下仍可通过文字和图标识别。
- 屏幕阅读器可读地点、结论、风险和图表替代摘要。

## 8. 性能测试

初始基线：

| 场景 | 目标 |
| --- | --- |
| 缓存命中分析 | P95 <= 2 秒，错误率 < 1% |
| Provider 回源分析 | P95 <= 5 秒（供应商 SLA 内） |
| 100 并发相同地点 | 单航班回源，Provider 调用接近 1 次 |
| 168 小时结果 | 响应体和渲染无明显卡顿，按需加载明细 |
| 30 分钟稳定性 | 无连接池耗尽、内存持续增长或缓存锁泄漏 |

性能测试使用 Provider Stub，另行记录真实 Provider 延迟，不用付费 API 承受压测流量。

## 9. 故障与恢复测试

- Redis 启动失败、运行中断开和恢复。
- PostgreSQL 短暂断连、只读、磁盘不足和迁移缺失。
- Open-Meteo Weather 和 Marine 分别连续超时、独立熔断并在半开后恢复。
- Stormglass 达到每日预算后关闭付费 fallback，缓存和基础路径保持可用。
- WorldTides Credit 告警、接口失败和恢复。
- AI 限流、超时、错误 Schema 和事实不一致。
- 容器重启、SignalR 断线、反向代理 WebSocket 禁用。
- 备份恢复后应用能够读取地点、用户和历史分析。

## 10. 安全测试

- 收藏/历史/设置的 IDOR 和批量越权。
- Cookie 安全属性、CSRF、防暴力破解和限流绕过。
- 地点名、Provider 错误和 AI 文本中的 XSS 载荷。
- 日志、ProblemDetails、健康检查和管理页不泄露 Secret。
- 管理员算法发布要求正确 Policy 和审计。
- NuGet、容器镜像和前端依赖漏洞扫描。

## 11. 缺陷等级

| 等级 | 定义 | 发布要求 |
| --- | --- | --- |
| S1 | 错误安全结论、越权、数据破坏、核心不可用 | 必须修复，停止发布 |
| S2 | 主要功能错误、降级失败、明显性能回归 | 必须修复或经正式风险接受 |
| S3 | 次要功能/兼容性问题，有合理绕过 | 可带计划发布 |
| S4 | 文案、轻微样式和低影响问题 | 进入待办 |

## 12. 准入与准出

准入：需求和算法版本冻结、测试环境/样本/Provider Stub 可用、迁移完成、监控可观测。

准出：P0/S1/S2 关闭；黄金样本 100% 通过；关键 API/E2E 通过；性能达到基线；无高危未处理漏洞；部署、回滚和恢复演练完成。
