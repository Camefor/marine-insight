# 日志设计

## 1. 设计目标

- 快速定位查询、Provider、标准化、评分和 AI 降级问题。
- 通过 TraceId 将浏览器、API、Provider、数据库和后台任务串联。
- 支持性能、配额、缓存和算法质量分析。
- 保护 API Key、令牌、用户身份和精确位置等敏感信息。

## 2. 日志分类

| 类型 | 用途 | 默认级别 | 保存建议 |
| --- | --- | --- | --- |
| 应用日志 | 用例执行、状态变化、错误 | Information | 30 天 |
| HTTP 访问日志 | 路径、状态、耗时、主体摘要 | Information | 30 天 |
| Provider 日志 | 外部调用、配额、降级、熔断 | Information/Warning | 30-90 天 |
| 分析日志 | 算法版本、等级、规则代码 | Information | 90 天 |
| 审计日志 | 管理发布、配置和权限操作 | 独立审计级别 | >= 1 年 |
| 安全日志 | 登录失败、限流、越权 | Warning | 90 天以上 |
| 任务日志 | 预热、清理、重算、通知 | Information | 30 天 |

生产环境默认不记录 Debug/Trace，临时开启必须限定模块和时间。

## 3. 结构化字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `timestamp` | 是 | UTC 事件时间 |
| `level` | 是 | 日志级别 |
| `messageTemplate` | 是 | 稳定模板，不拼接大对象 |
| `traceId` / `spanId` | 是 | 调用链标识 |
| `eventId` | 是 | 稳定事件编号和名称 |
| `environment` / `service` / `version` | 是 | 部署上下文 |
| `userIdHash` | 否 | 必要时使用不可逆摘要，不记录邮箱 |
| `locationGrid` | 否 | 网格化位置，避免默认记录精确坐标 |
| `provider` / `model` | 否 | 数据源上下文 |
| `forecastBatchIds` / `analysisId` | 否 | Weather/Marine/Tide 来源批次集合与业务追溯标识 |
| `algorithmVersion` | 否 | 分析版本 |
| `cacheStatus` | 否 | L1/L2/Miss/Stale |
| `durationMs` | 否 | 操作耗时 |
| `errorCode` | 否 | 稳定错误分类 |

## 4. 事件编号

| 范围 | 模块 | 示例 |
| --- | --- | --- |
| 1000-1999 | HTTP/API | 请求开始、完成、验证失败 |
| 2000-2999 | Provider | 调用成功、限流、熔断、字段异常 |
| 3000-3999 | Forecast | 标准化、质量校验、批次保存 |
| 4000-4999 | Analysis | Gate、评分、时间窗、Unknown |
| 5000-5999 | AI | 调用、Schema 失败、模板降级 |
| 6000-6999 | Cache | 命中、穿透锁、序列化错误 |
| 7000-7999 | Security/Audit | 登录、权限拒绝、配置发布 |
| 8000-8999 | Background Jobs | 预热、清理、重算、通知 |

## 5. 记录规范

- 使用结构化模板：`Provider {Provider} failed with {ErrorCode}`，不使用字符串插值展开完整响应。
- Information 记录业务里程碑，不记录每个循环点位。
- Warning 表示已降级或需要关注但请求可处理；Error 表示请求失败或数据一致性受影响。
- 异常日志记录异常对象、稳定错误码和必要上下文，不向用户返回内部堆栈。
- 禁止记录密码、Cookie、Authorization、API Key、连接字符串和完整 AI 提示词。
- 第三方响应仅在受控诊断模式按采样脱敏记录，设置短期保留。

## 6. 调用链追踪

采用 W3C Trace Context 和 OpenTelemetry：

```text
Blazor interaction
  -> POST /api/v1/marine-analyses
     -> cache lookup
     -> Open-Meteo Weather + Marine HTTP spans
     -> optional Stormglass/WorldTides spans
     -> ForecastSnapshot assembly span
     -> forecast normalization
     -> analysis engine
     -> PostgreSQL command
     -> optional AI span
```

Provider 请求传递 `traceparent` 仅在供应商允许且安全的情况下启用。后台任务创建新的根 Span，并关联触发它的业务事件。

## 7. 指标与看板

核心指标：

- `marine_query_total`、成功率、P50/P95/P99。
- `provider_request_total`、错误率、限流率、配额余额、熔断状态。
- `forecast_quality_total` 按 Valid/Partial/Stale/Invalid 分组。
- `analysis_result_total` 按风险等级、活动和算法版本分组。
- `cache_hit_ratio`、Stale 降级率、回源锁等待。
- `ai_request_total`、Token、Schema 失败和模板降级率。
- 数据库连接池、慢查询和迁移状态。

业务看板不展示可识别个人的精确位置轨迹。

## 8. 告警规则

| 告警 | 条件示例 | 级别 |
| --- | --- | --- |
| API 错误率高 | 5xx > 5% 持续 5 分钟 | Critical |
| Provider 不可用 | 主 Provider 失败 > 30% 持续 10 分钟 | High |
| Stale 降级升高 | 降级率 > 10% 持续 10 分钟 | High |
| 数据质量异常 | Invalid/Partial 比例突增 | High |
| 缓存命中骤降 | 命中率 < 50% 持续 15 分钟 | Medium |
| Provider 配额不足 | 剩余配额低于 20% | Medium |
| AI Schema 失败 | > 2% 持续 15 分钟 | Medium |
| 算法 Unknown 激增 | 相对基线明显增加 | High |

告警应包含环境、时间、影响范围、看板和 Runbook 链接，避免直接附带敏感请求内容。

## 9. 存储与访问

- 开发环境输出控制台和本地结构化文件。
- 生产通过 OpenTelemetry Collector 或平台 Agent 发送到集中日志系统。
- 审计日志使用独立索引/存储和更严格访问策略。
- 日志访问只授予开发运维必要人员，并记录查询审计。
- 按保留策略自动归档和删除，禁止无限期积累。
