# 腾讯云生产部署手册

## 1. 文档定位

本手册面向在 **腾讯云轻量应用服务器（Lighthouse）** 上部署 Marine Insight `v1.0` 的运维人员，覆盖从服务器初始化、Docker 安装、密钥准备、构建启动、HTTPS、备份恢复到升级回滚的完整 Linux 操作流程。

目标环境与命令均为 **Linux 原生 bash**（服务器为 Ubuntu Server 24.04 LTS，与开发机 Windows PowerShell 无关）。仓库内 `scripts/*.ps1` 是开发机辅助脚本，本手册给出对应的服务器端 bash 等价命令。

本手册是 [18-部署文档](./18-部署文档.md) 与 [19-Docker部署](./19-Docker部署.md) 在腾讯云轻量环境下的落地执行手册；拓扑、镜像、Compose 与 Secret 规范以 19 号文档为准。

## 2. 目标环境核对

| 项 | 期望值 | 说明 |
| --- | --- | --- |
| 云产品 | 腾讯云轻量应用服务器 | Lighthouse 用「防火墙」而非 CVM 安全组 |
| 操作系统 | Ubuntu Server 24.04 LTS 64bit | 命令按 24.04 编写 |
| Docker | Docker Engine 29 + Compose v2 | 使用 `docker compose`（V2 插件，内置） |
| 数据库 | PostgreSQL（容器，部署时 18.4） | 镜像 `postgres:latest` |
| 反向代理 | Caddy 2.10（容器） | 自动签发/续期 Let's Encrypt 证书 |
| 应用 | .NET 10 Blazor Web（容器） | 非 root，内部端口 8080 |
| 域名 | `marine.example.com`（示例） | 下文所有域名均以此为占位 |

## 3. 部署拓扑

`compose.yaml` 定义四个服务，数据库仅入内部网络，Caddy 是唯一公开入口：

| 服务 | 镜像/构建 | 端口 | 网络 | 持久化 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `postgres` | `postgres:latest` | 5432（内部） | `data` | `postgres-data`（挂载 `/var/lib/postgresql`）、`./backups:/backups` | 主数据库，`pg_isready` 健康检查；18+ 镜像需挂载到 `/var/lib/postgresql` 而非 `/var/lib/postgresql/data` |
| `migrate` | 构建自 `Dockerfile` | 无 | `data` | 无 | 一次性 `--migrate`，成功后退出（`restart: no`） |
| `web` | 构建自 `Dockerfile` | 8080（内部） | `ingress` + `data` | `data-protection` | Blazor/API/认证，非 root |
| `reverse-proxy` | `caddy:2.10-alpine` | 80 / 443（公开） | `ingress`（固定 172.30.0.10） | `caddy-data`、`caddy-config` | TLS、压缩、安全头、反向代理 |

```
                 ┌───────────────────────── ingress 172.30.0.0/24 ─────────────────────────┐
                 │                                                                          │
  Internet ──► reverse-proxy (172.30.0.10, :80/:443) ──► web (:8080)                        │
                                                              │                              │
                                                              │  ┌──────── data (internal) ┐  │
                                                              └──► migrate ──► postgres     │  │
                                                                  └────────────────────────┘  │
                                                                                             │
                                                                  web ──► postgres (data) ────┘
```

- 应用启动顺序由 Compose 依赖表达：`postgres` 健康 → `migrate` 成功退出 → `web` 健康 → `reverse-proxy`。
- `ReverseProxy__KnownProxies__0=172.30.0.10` 已写死为 Caddy 的固定地址，用于 `ForwardedHeaders` 解析真实客户端 IP（支撑账号限流）。
- 连接字符串、Postgres 密码通过 Key-per-file Secret 注入；Web 启动时 `AddKeyPerFile("/run/secrets")` 读取 `/run/secrets` 下的密钥文件。

## 4. 前置准备

### 4.1 域名与 DNS

1. 准备一个已实名认证的域名，并解析一条 **A 记录** 指向轻量服务器公网 IP（`marine.example.com → <公网IP>`）。
2. 等待 DNS 生效（`dig marine.example.com` 或 `nslookup` 验证）。

### 4.2 ICP 备案（仅中国大陆地域）

- 轻量服务器位于 **中国大陆地域** 时，域名须完成 **ICP 备案** 才能通过 80/443 对外提供 Web 服务；腾讯云会拦截未备案域名的 HTTP/HTTPS 流量。
- 服务器位于 **中国香港或海外地域** 时无需备案。
- 备案周期通常 1~2 周，需提前办理；Caddy 自动 HTTPS 依赖 80 端口可达，备案未通过时无法签发证书。

### 4.3 腾讯云防火墙放行端口

轻量应用服务器在控制台「防火墙」中管理放行规则（默认通常已放行 `22 / 80 / 443 / 8080 / 8888`）。请确认：

| 端口 | 协议 | 用途 |
| --- | --- | --- |
| 22 | TCP | SSH 远程登录 |
| 80 | TCP | HTTP（Caddy，用于证书 HTTP-01 校验与跳转） |
| 443 | TCP | HTTPS |
| 443 | UDP | HTTP/3（可选，Caddy 已监听 443/udp） |

> 切勿放行 5432（PostgreSQL）、8080（Web）到公网；数据库与 Web 端口仅容器内部网络可见。

## 5. 服务器初始化

以普通 sudo 用户（非 root）登录：

```bash
ssh ubuntu@<公网IP>            # 腾讯云 Lighthouse 默认用户常为 ubuntu 或 lighthouse

# 更新系统并安装基础工具
sudo apt update && sudo apt upgrade -y
sudo apt install -y ca-certificates curl gnupg git openssl ufw

# 设置时区（容器内始终 UTC，宿主机时区仅影响 cron 与日志查看）
sudo timedatectl set-timezone Asia/Shanghai
```

> 备份文件与日志会占用磁盘。轻量服务器磁盘较小，建议在「备份与恢复」一节后配置定时清理，或挂载独立数据盘存放 `./backups`。

## 6. 安装 Docker Engine 29 + Compose v2

使用 Docker 官方 apt 源安装（比 Ubuntu 自带的 `docker.io` 更新、附带 Compose v2 插件）：

```bash
# 添加官方 GPG Key 与 apt 源
sudo install -m 0755 -d /etc/apt/keyrings
curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
  sudo gpg --dearmor -o /etc/apt/keyrings/docker.gpg
sudo chmod a+r /etc/apt/keyrings/docker.gpg

echo \
  "deb [arch=$(dpkg --print-architecture) signed-by=/etc/apt/keyrings/docker.gpg] \
  https://download.docker.com/linux/ubuntu \
  $(. /etc/os-release && echo "$VERSION_CODENAME") stable" | \
  sudo tee /etc/apt/sources.list.d/docker.list > /dev/null

sudo apt update
sudo apt install -y docker-ce docker-ce-cli containerd.io docker-buildx-plugin docker-compose-plugin

# 将当前用户加入 docker 组（免 sudo 运行 docker），重新登录后生效
sudo usermod -aG docker "$USER"

# 验证
docker --version
docker compose version
```

退出并重新登录（或 `newgrp docker`）后，确认可免 sudo 运行 `docker ps`。

## 7. 获取代码

```bash
cd /opt
sudo mkdir -p marine-insight && sudo chown "$USER" marine-insight
git clone <仓库地址> marine-insight
cd marine-insight
```

若服务器无法访问 Git 仓库，可在开发机 `git archive` 或打包源码后上传（`scp -r`），确保 `Dockerfile`、`compose.yaml`、`compose.worldtides.yaml`、`deploy/Caddyfile`、`src/`、`tests/` 等均在位。

## 8. 准备密钥（Secret 文件）

真实密钥必须放在 **仓库外** 的受限目录，只把「文件路径」通过 `.env` 交给 Compose。仓库内的 `deploy/secrets/*.example` 仅为一次性本地占位，禁止在生产使用。

```bash
# 1) 创建仓库外的密钥目录（权限收紧）
sudo mkdir -p /etc/marine-insight/secrets
sudo chown "$USER" /etc/marine-insight/secrets
chmod 700 /etc/marine-insight/secrets

# 2) 生成强随机 Postgres 密码（去除末尾换行，避免密码被多读一个换行符）
openssl rand -base64 24 | tr -d '\n' > /etc/marine-insight/secrets/postgres_password

# 3) 生成连接字符串（主机名 postgres 指向 compose 服务名，密码与上面一致）
PW=$(cat /etc/marine-insight/secrets/postgres_password)
printf 'Host=postgres;Port=5432;Database=marine_insight;Username=marine_insight;Password=%s;Include Error Detail=false' \
  "$PW" > /etc/marine-insight/secrets/ConnectionStrings__MarineInsight

# 4) 校验（两个文件内容一致，密码不含换行）
wc -c /etc/marine-insight/secrets/postgres_password /etc/marine-insight/secrets/ConnectionStrings__MarineInsight
```

## 9. 生产配置

### 9.1 关闭 AI（默认，必须）

`src/MarineInsight.Web/appsettings.json` 出厂默认 `AI.Enabled=true` 且不含 `AI.ApiKey`；`ExplanationOptions.Validate()` 在「启用但无 Key」时抛异常，而 `AddExplanationProvider` 使用 `ValidateOnStart()`。若不显式关闭或注入 Key，**`web` 容器会在启动阶段直接崩溃**。

生产默认关闭 AI（分析退化为确定性规则模板，不影响任何评分/安全结论），后续需要时再按 20.2 启用。创建 `compose.production.yaml`：

```yaml
# compose.production.yaml —— 生产环境覆盖（不含任何密钥）
services:
    web:
        environment:
            AI__Enabled: "false"
```

> `migrate` 服务虽也构建同一镜像，但其 `--migrate` 路径在主机启动前即返回，不触发 `ValidateOnStart`，故无需覆盖。

### 9.2 站点地址与密钥路径

在项目根目录创建 `.env`（Compose 自动加载，**只存路径，不存密钥值**）：

```bash
cat > .env <<'EOF'
MARINE_INSIGHT_SITE_ADDRESS=https://marine.example.com
MARINE_INSIGHT_POSTGRES_PASSWORD_FILE=/etc/marine-insight/secrets/postgres_password
MARINE_INSIGHT_DB_CONNECTION_SECRET_FILE=/etc/marine-insight/secrets/ConnectionStrings__MarineInsight
EOF
```

`.env` 中三项含义：

| 变量 | 含义 |
| --- | --- |
| `MARINE_INSIGHT_SITE_ADDRESS` | Caddy 站点地址；填真实域名后 Caddy 自动签发 HTTPS 证书 |
| `MARINE_INSIGHT_POSTGRES_PASSWORD_FILE` | 指向 Postgres 密码文件 |
| `MARINE_INSIGHT_DB_CONNECTION_SECRET_FILE` | 指向连接字符串文件 |

### 9.3 生产启动命令

```bash
docker compose -f compose.yaml -f compose.production.yaml up -d --build
```

## 10. 构建镜像

首次或代码变更后构建（`--pull` 拉取最新基础镜像）：

```bash
docker compose -f compose.yaml -f compose.production.yaml build --pull
```

多阶段 Dockerfile：`sdk:10.0` 构建 → `aspnet:10.0` 运行时，`dotnet publish --configuration Release`（不指定 `--no-restore`，确保 `_framework` 框架静态资源被解析），运行时以非 root `$APP_UID` 运行，`EXPOSE 8080`，健康检查打 `/health/live`。

## 11. 首次启动与迁移

```bash
cd /opt/marine-insight
docker compose -f compose.yaml -f compose.production.yaml up -d
```

启动流程：Postgres 启动并通过 `pg_isready` → `migrate` 一次性执行 EF Core 迁移（`--migrate`）并退出 → `web` 启动并通过 `/health/live` → `reverse-proxy` 就绪。

观察状态与日志：

```bash
docker compose -f compose.yaml -f compose.production.yaml ps
docker compose -f compose.yaml -f compose.production.yaml logs -f web
docker compose -f compose.yaml -f compose.production.yaml logs migrate   # 确认迁移成功退出
```

若需手工迁移（如外部数据库），仓库已提供幂等脚本产物 `deploy/postgresql-migrations.sql`（由 `scripts/generate-migration-sql.ps1` 生成）。

## 13. 域名与 HTTPS（Let's Encrypt）

`.env` 中 `MARINE_INSIGHT_SITE_ADDRESS=https://marine.example.com` 会传入 Caddy 容器；Caddy 启动时：

1. 校验域名解析到本机公网 IP；
2. 通过 80 端口完成 HTTP-01 校验；
3. 自动向 Let's Encrypt 申请并续期证书。

校验：

```bash
curl -fsS -o /dev/null -w 'https=%{http_code}\n' https://marine.example.com/health/live
curl -sSI https://marine.example.com/ | grep -i 'strict-transport-security'
```

若证书未签发，排查顺序：DNS A 记录是否生效 → 80 端口防火墙是否放行 → 备案是否通过 → 查看 `docker compose logs reverse-proxy`。

## 14. 备份

自定义格式逻辑备份写入宿主 `./backups/`（已挂载到 Postgres 容器的 `/backups`），备份文件须另行加密、异机复制并设置保留策略：

```bash
cd /opt/marine-insight
mkdir -p backups
FILENAME="marine-insight-$(date -u +%Y%m%d-%H%M%S).dump"
docker compose -f compose.yaml -f compose.production.yaml exec -T postgres pg_dump \
  --username marine_insight \
  --dbname marine_insight \
  --format custom \
  --no-owner \
  --no-privileges \
  --file "/backups/$FILENAME"
ls -lh "backups/$FILENAME"
```

定时备份（每日 03:17 UTC，避开整点）：

```bash
( crontab -l 2>/dev/null; \
  echo '17 3 * * * cd /opt/marine-insight && docker compose -f compose.yaml -f compose.production.yaml exec -T postgres pg_dump --username marine_insight --dbname marine_insight --format custom --no-owner --no-privileges --file "/backups/marine-insight-$(date -u +\%Y\%m\%d-\%H\%M\%S).dump"' \
) | crontab -
```

## 15. 恢复

恢复是破坏性操作：先停 `web`，`pg_restore --clean --if-exists` 覆盖，校验迁移历史后重启：

```bash
cd /opt/marine-insight
FILENAME="marine-insight-20260813-031700.dump"   # 换成真实备份文件名

# 1) 停 Web
docker compose -f compose.yaml -f compose.production.yaml stop web

# 2) 恢复
docker compose -f compose.yaml -f compose.production.yaml exec -T postgres pg_restore \
  --username marine_insight \
  --dbname marine_insight \
  --clean --if-exists \
  --no-owner --no-privileges \
  "/backups/$FILENAME"

# 3) 校验迁移历史存在
docker compose -f compose.yaml -f compose.production.yaml exec -T postgres psql \
  --username marine_insight \
  --dbname marine_insight \
  --tuples-only \
  --command 'SELECT COUNT(*) FROM "__EFMigrationsHistory";'

# 4) 重启 Web
docker compose -f compose.yaml -f compose.production.yaml start web
```

> 仅接受 `./backups` 目录内的文件，避免误恢复任意路径；恢复前确认目标环境正确。

## 16. 升级与回滚

```bash
cd /opt/marine-insight

# 1) 备份
FILENAME="marine-insight-$(date -u +%Y%m%d-%H%M%S).dump"
docker compose -f compose.yaml -f compose.production.yaml exec -T postgres pg_dump \
  --username marine_insight --dbname marine_insight \
  --format custom --no-owner --no-privileges --file "/backups/$FILENAME"

# 2) 拉取新代码并构建
git pull
docker compose -f compose.yaml -f compose.production.yaml build --pull

# 3) 重建（migrate 服务自动执行新增迁移）
docker compose -f compose.yaml -f compose.production.yaml up -d

# 4) 验证健康与关键页
curl -fsS -o /dev/null -w 'ready=%{http_code}\n' https://marine.example.com/health/ready

# 5) 回滚：切回上一镜像/提交
git checkout <上一版本 tag 或 commit>
docker compose -f compose.yaml -f compose.production.yaml up -d --build
```

回滚原则：镜像用版本化标签（`v1.0.0` + Git SHA），不依赖可变 `latest`；数据库不回滚（EF Core 迁移只前进，遇破坏性变更用「备份 + 恢复」回退数据）。算法阈值问题优先回滚算法版本而非整站。

## 17. 日志与监控

应用日志以结构化 JSON 输出到容器 stdout：

```bash
docker compose -f compose.yaml -f compose.production.yaml logs -f web
docker compose -f compose.yaml -f compose.production.yaml logs -f reverse-proxy
```

观察指标：`docker compose ps` 健康状态、5xx 比例、Stale 降级、数据质量（Missing/Unknown）、Provider 配额与 AI 降级日志（`analysis_degraded` 事件）。

若配置了 `OpenTelemetry__Endpoint`，Trace/指标会转发至 OTel Collector；未配置时仅本地结构化日志。

## 18. 故障排查

| 现象 | 检查 | 处理 |
| --- | --- | --- |
| `web` 启动即崩溃 | `docker compose logs web` 报 AI 配置错误 | 确认 `compose.production.yaml` 已设置 `AI__Enabled=false`，或已注入 `AI__ApiKey` |
| `postgres` 不健康，日志报 `unused mount/volume` | 18+ 镜像数据目录变更 | 将命名卷挂载点改为 `/var/lib/postgresql`；已有旧卷按需 `docker compose down -v` 重建 |
| `migrate` 未成功 | `docker compose logs migrate`、Postgres 健康 | 检查连接字符串 Secret、密码一致、`data` 网络连通 |
| `reverse-proxy` 无证书 | 域名解析、80 端口、备案 | 核对 DNS A 记录与防火墙 80 放行；`logs reverse-proxy` |
| 查询持续 503 | Open-Meteo Weather/Marine、外网出口 | 分域检查 `api.open-meteo.com` 与 `marine-api.open-meteo.com` 可达性，确认容器可出网 |
| 潮汐为空 | WorldTides 开关、Credit、缓存 | 未启用或余额耗尽时基础海况继续运行，属预期降级 |
| 登录后会话频繁丢失 | `data-protection` 卷 | 确认 `data-protection` 卷挂载正常、未被删除，密钥持久化 |
| 磁盘告警 | `backups/`、Postgres 数据卷、镜像缓存 | 清理旧备份与 `docker system prune`，必要时挂数据盘 |

## 19. 安全基线

- 仅 22 / 80 / 443 对公网开放，数据库与应用端口不暴露。
- 密钥存放于仓库外受限目录（`chmod 700`），`.env` 只存路径不存值。
- Caddy 已下发 `X-Content-Type-Options: nosniff`、`Referrer-Policy`、`Permissions-Policy` 并移除 `Server` 头。
- 应用启用 HSTS、Cookie `Secure`/`HttpOnly`/`SameSite=Lax`、账号失败锁定与限流。
- 认证密码与 AI/WorldTides Key 不进入镜像层或普通环境变量列表。
- 上线后建议开启 `Identity:RequireConfirmedEmail` 并将登录限流策略调至生产强度。

## 20. 可选功能启用

### 20.1 WorldTides 潮汐

```bash
# 将纯 Key 写入仓库外文件
printf '你的WorldTidesKey' > /etc/marine-insight/secrets/worldtides_api_key

# .env 追加
echo 'MARINE_INSIGHT_WORLDTIDES_SECRET_FILE=/etc/marine-insight/secrets/worldtides_api_key' >> .env

# 叠加覆盖文件启动
docker compose -f compose.yaml -f compose.production.yaml -f compose.worldtides.yaml up -d
```

### 20.2 AI 解读（OpenAI 兼容，如 SiliconFlow/DeepSeek）

AI 关闭或失败时自动退化为规则模板，不阻塞分析。启用需提供 Key 并改回开关：

```yaml
# compose.ai.yaml —— AI 启用覆盖
services:
    web:
        environment:
            AI__Enabled: "true"
        secrets:
            - AI__ApiKey
secrets:
    AI__ApiKey:
        file: ${MARINE_INSIGHT_AI_SECRET_FILE:-./deploy/secrets/ai_api_key}
```

```bash
printf '你的AIKey' > /etc/marine-insight/secrets/ai_api_key
echo 'MARINE_INSIGHT_AI_SECRET_FILE=/etc/marine-insight/secrets/ai_api_key' >> .env

# 用 compose.ai.yaml 替代 compose.production.yaml 中的 AI 关闭项
docker compose -f compose.yaml -f compose.ai.yaml up -d
```

默认 `AI.BaseUrl=https://api.siliconflow.cn/v1`、`Model=deepseek-ai/DeepSeek-V3.2`；可通过 `AI__BaseUrl` / `AI__Model` 环境变量覆盖为其他 OpenAI 兼容服务（OpenAI/DeepSeek/Qwen/Moonshot/Ollama）。

### 20.3 天地图 Key（浏览器端）

天地图 Key 虽为浏览器端 Key（会出现在瓦片请求 URL 中），仍遵守「Key 不进入源码」规范，**不得写入 `appsettings.json`**，通过 key-per-file Secret 注入。未注入时地图选点降级为坐标输入，不阻塞查询。

```bash
# 将纯 Key 写入仓库外文件
printf '你的天地图Key' > /etc/marine-insight/secrets/tianditu_key

# .env 追加
echo 'MARINE_INSIGHT_TIANDITU_SECRET_FILE=/etc/marine-insight/secrets/tianditu_key' >> .env

# 叠加覆盖文件启动
docker compose -f compose.yaml -f compose.production.yaml -f compose.tianditu.yaml up -d
```
